# 0.1.1

- VileMK no longer uses a separate ZMK config repo. `config/`, `build.yaml` and `.zmk/` live in the VileMK folder, and the `--repo` flag and `$ZMK_CONFIG` are gone.
- A saved variant's build.yaml no longer names a `KEYMAP_FILE`; building the variant supplies it. `make check` warns about one left in `build.yaml`.
- A ZMK link under the logo opens settings for which ZMK the project uses. Update fetches ZMK's board data and pins the exact commit in `config/west.yml`; `make zmk` does the same from the command line.
- **Build firmware** builds the variant with Docker and writes the `.uf2` files into `variants/<name>/firmware/`. It shows the build log as it runs and can cancel it. `make firmware ARGS=<name>` does the same from the command line.
- The first build downloads ZMK's build image and all of ZMK and Zephyr, which takes several minutes; a later build of a split keyboard takes about 20 seconds. Without Docker the button is off and says why.
- Deleting a variant also deletes its built firmware.
- Build options (include reset, the keyboard's add-on parts, Build firmware) are in their own **Build** panel under the Save button. It starts collapsed and shows the chosen options in its heading.
- Saving is one **Save** button. On a variant it offers **Overwrite** or **Save as…**; Save as asks for the new name in a dialog.
- Importing a keymap for a keyboard you don't have now says which vendor module the keyboard comes from and where to add it. Exported keymaps carry this in a comment line, so they still build as before in a regular ZMK config repo.
- **Add a keyboard** in the sidebar lists every keyboard in ZMK and in the modules you have installed. Adding one adds its halves to `build.yaml` and copies the keyboard's settings file into `config/` if it has one; the keymap stays under **Vendor defaults**, and you start a variant from it; for a keyboard that plugs into a separate controller, you pick the controller. The same dialog removes a keyboard. `python3 -m vilemk.keyboards` does the same from the command line.
- Deleting a combo, macro or other custom behavior, deleting or overwriting a variant, removing a keyboard and switching ZMK now ask in the app's own dialog instead of a browser popup.
- With **compare with…** on, hovering a changed key for a moment shows what it does now and what it did before, in full. The labels on the key itself are cut short when they don't fit.
- **Build firmware** now uses the Build panel's current choices (include reset, add-on parts) even if you haven't saved, and updates the variant's build.yaml to match. Before, turning reset off and building without saving still built the reset files.
- The build dialog has **Open folder**, which opens the firmware folder in your file manager, and **Copy path**.
- The build dialog lists the files already in the firmware folder. The ones the next build replaces are highlighted in orange, and any it will remove are struck out.
- The app always uses the dark Evening in Kyoto theme. The light scheme is gone.
- **Add a keyboard** can fetch a keyboard module from GitHub: paste the repository URL and a branch or tag, and its keyboards appear in the list to add. The exact commit is pinned in `config/west.yml`. `make module ARGS="add <url> --ref main"` does the same from the command line.
- The same dialog lists your modules with **Update**, which fetches the latest commit of the branch or tag, and **Remove**. Remove is refused while `build.yaml` or a variant still uses one of the module's keyboards.
- The sidebar no longer has an **In this config** group. Keymaps in `config/` are never built (a variant build names its own keymap), so the list shows only **Saved variations** and **Vendor defaults**. `settings_reset` is no longer listed as a keyboard, and when a keyboard's vendor ships two keymaps, each says which it is: **board default** or **vendor's firmware**.
- Each keyboard in the sidebar has a **⋮** button with **Export as picture** and **Delete**. Delete on a variation deletes it; on a vendor default it takes the keyboard out of the project, and its module with it. That is refused while variations use the keyboard, and the dialog lists them.
- A vendor's second keymap for a keyboard (the one in its own `config/`) is listed under the keyboard's board default instead of beside it.
- A module's **Update** now downloads the new version and checks your variations against it before replacing anything. If one would break (a key removed from the layout, a board renamed), the module is left as it was and the dialog lists what would break; **Overwrite** installs the new version anyway.
- The status line under the Save button (for example "deleted bat43") has a **×** to dismiss it, and it clears when you pick another keymap, layer or layout.
- **Export keymap** moved from the board bar to the sidebar **⋮** menu, and works for vendor defaults as well as variations. It opens a dialog where you choose **Save as…** (pick where to save the `.keymap`) or **Copy to clipboard**, and can tick **include key positions** to add a comment at the top of the file that draws the layout with each key's position number.
- The **key positions** checkbox moved from the bar at the top to just under the layer tabs, above the keyboard it numbers.
- **+ layer** asks for the layer's name in the app's own dialog instead of a browser popup.
- The **Build** panel stands out in the accent colour, with a blinking cursor in its heading while it is closed.
- The **compare with…** list stretches to the full width of the page.
- **Export as picture** no longer prints the keymap's file path under the title.
- **Build firmware** now stops with a message when the variant's keyboard is not installed (its module was removed, or the keymap came from someone else), instead of starting a build that fails in Docker.
- Modules can be renamed in **Add a keyboard**. The new name is only what the app shows; the module keeps its real name everywhere else.
- Removing a module now tells you which of its files could not be deleted, if any.
- Saving a variant no longer overwrites a layer's encoder bindings when the keymap lists them before the key bindings.
- **Flash** in the **Build** panel's heading, and **Flash firmware** in a variation's **⋮** menu, open a dialog that copies the firmware onto the keyboard for you. Connect the keyboard (or one half) with a USB cable and double-tap reset; once the app sees it, click **Copy** beside the file for that half. It looks for 10 seconds and then asks whether to keep looking.
- **Flash** is greyed out until the variation is built, and again once it has unsaved changes or has been saved since the last build. The build dialog shows **Flash** only after a build finishes.
- After **Copy** in the flash dialog, the app waits until the keyboard restarts and then says it is flashed and the cable can come out. After a `settings_reset` file it says so instead, and tells you to keep the cable in, double-tap reset again and copy the firmware. It no longer starts looking for a keyboard straight after a flash and ends with "Keyboard not found".
- The flash dialog marks each file you have copied with **✓ flashed** instead of renaming its button to **Copy again**.
- Buttons you can't use right now (such as **Copy** before a keyboard is found) are dimmed.
