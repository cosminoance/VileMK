# 0.2.0

- VileMK no longer uses a separate ZMK config repo. `config/`, `build.yaml` and `.zmk/` live in the VileMK folder, and the `--repo` flag and `$ZMK_CONFIG` are gone.
- A ZMK link under the logo opens settings for which ZMK the project uses. Update fetches ZMK's board data and pins the exact commit in `config/west.yml`; `make zmk` does the same from the command line.
- **Build firmware** builds a variant with Docker and writes the `.uf2` files into `variants/<name>/firmware/`, with a live build log and a cancel button. `make firmware ARGS=<name>` does the same from the command line.
- **Flash** copies the built firmware onto the keyboard from inside the app. Connect a half with USB, double-tap reset, and click **Copy** beside its file; the app tells you when the keyboard has restarted and the cable can come out.
- Build options (include reset, add-on parts, Build firmware, Flash) are in their own **Build** panel under the Save button.
- Saving is one **Save** button. On a variant it offers **Overwrite** or **Save as…**.
- **Add a keyboard** in the sidebar lists every keyboard in ZMK and in your installed modules, and adds or removes one from the project. `python3 -m vilemk.keyboards` does the same from the command line.
- **Add a keyboard** can also fetch a keyboard module from GitHub by URL and branch or tag, pinning the exact commit. Installed modules can be updated, renamed and removed; an update checks your variations against the new version before replacing anything. `make module` does the same from the command line.
- Each keyboard in the sidebar has a **⋮** menu with **Export as picture**, **Export keymap**, **Flash firmware** and **Delete**.
- **Export keymap** saves the `.keymap` to a file or copies it to the clipboard, optionally with a comment that draws the layout with each key's position number.
- The sidebar lists only **Saved variations** and **Vendor defaults**. When a vendor ships two keymaps for a keyboard, each says which it is.
- With **compare with…** on, hovering a changed key shows what it does now and what it did before.
- **Ctrl+S** (Cmd+S on a Mac) saves: it overwrites the open variant, or opens **Save as…** on a vendor keymap.
- Reloading or closing the page with unsaved key changes asks before leaving.
- **include reset** starts from what the variant was saved with, and **Flash** stays off after you change it or the add-on parts until you build again.
- With both halves in their bootloader at once, **Flash** asks you to unplug one before copying, since it cannot tell the halves apart.
- The foot of the sidebar links to VileMK on GitHub and to its issue tracker for reporting a bug.
- Picking another keyboard while the current one has unsaved key changes asks before dropping them. Before, the changes carried over onto the next keyboard.
- The page remembers the keyboard you had open, whether the sidebar was collapsed, and the key positions toggle across reloads.
- The browser tab shows the open keymap's name, with a dot while it has unsaved changes.
- Escape clears the sidebar filter.
- Saving while a key's binding is typed but not applied yet includes that binding, as if you had pressed Enter first.
- A half-written VileDance, macro, combo, modifier or layer in the editor now counts as unsaved: leaving the page asks first, and the tab shows the dot.
- **+ layer** can copy a layer from one of your saved variations on another keyboard: pick **Layer from another keyboard…**, search for the variation, pick the layer and **Import**. Keys are matched by position number, so it works between keyboards with different key counts: extra keys stay transparent, and bindings past the smaller keyboard's last key are left out and listed before you import. The keymap's own layers are not touched.
- A variant for a keyboard whose vendor names every build entry after its own firmware now gets the vendor's boards and shields in its build.yaml instead of a guessed board, and a dialog says where they came from.
- Keyboards whose shield folder is named differently from the shield (such as `charybdis-bt/`) are no longer reported as not installed.
- **Build firmware** stops before building when a shield is defined in two folders, names both, and says whether to remove a module or fork one.
- `TROUBLESHOOTING.md`, linked from the README, explains what a keyboard module needs, how to spot a repository that only builds through its owner's CI, and what each module and build error means.
